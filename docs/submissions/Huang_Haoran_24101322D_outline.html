Project Title

RecallLab — A Spatial Recall Reader for Hierarchical Course Material

A full-stack web application for recalling structured study material by navigating it as a file system.

03

Abstract — The Functions of RecallLab

Existing study tools flatten course material into shuffled decks of isolated questions, discarding the structure a learner actually uses as a retrieval cue — the lecture, the section, the topic a concept belongs to. RecallLab keeps that structure and makes it the interface: material is stored as a tree of folders and cards, each card carrying a prompt on its face and an answer on its back, and the learner moves through that tree spatially.

Three functions define the product. First, hierarchical browsing: a spine shows the entire tree, a breadcrumb shows the current path, and the main area tiles the current level, with folders and cards visually distinguished. Built on the History API, every level is addressable by URL, the back button means “ascend one level”, and any folder can be shared as a deep link.

Second, Focus Mode. Entering it narrows the screen to a single card on a dark stage while the rest of the level recedes into a stack behind it. Clicking the card flips it to reveal the answer. Dragging it away throws it off the stage and lets the next sibling rise into focus, carrying the velocity of the gesture. Holding it for 450 milliseconds pulls it out into a floating window that hovers above the focused card and can be dragged anywhere, while focus moves on. When the focused item is a folder, activating it descends into that folder’s level: the tree is traversed by focusing, never by opening a dialog.

Third, tree editing. An edit mode overlays both the file page and Focus Mode and provides complete create, read, update and delete over the tree — renaming, editing card bodies and answers, creating folders and cards, deleting a subtree behind a confirmation that states how many items will be removed, moving a card between folders, and reordering siblings by drag. Scope is deliberately narrow: no accounts, no AI generation, no spaced-repetition scheduling, so recall is carried by the interaction rather than by a scoring system.

04

Implementation

Front end Vanilla HTML, CSS and ES modules — no build step, no framework · Back end Node.js and Express, REST over JSON · Data PostgreSQL via the pg driver, one adjacency-list table · Deployment Vercel serverless function with Supabase Postgres, HTTPS
